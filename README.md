# PQC Certificate

Post-quantum certificates on QoreChain testnet — built for the QoreChain
Developer Fest **"Build Before Q-Day"**, category **Quantum Pass** (solo,
Level Quantum Pass).

A certificate binds a document hash to an issuer, a title and a recipient,
and stores the record on-chain so anyone can verify that a document was
certified by a given address at a given time. Only the `keccak256` hash of a
document is stored — never the file itself.

Two issuance paths:

- **Plain issuance** (`issueCertificate`): the transaction itself is
  hybrid-signed when sent through QoreX (secp256k1 + ML-DSA-87). This is
  what the Quantum Pass category requires.
- **PQ-proof issuance** (`issueCertificateWithPQProof`): additionally verifies
  an ML-DSA-87 signature over the document hash **on-chain**, through the
  QoreChain PQC precompile (`0x0a01`, testnet-only). The certificate is then
  marked `pqVerified`.

## Architecture & upgrade path

- `IPQCVerifier` / `PQCVerifier` are deliberately separate from the registry
  so the **Post-Quantum dApp upgrade ("Quantum-Safe Vault")** can reuse the
  same verification path for its scoped-window + `pqcVerify` checks, and so
  the vault can call `keyStatus` to confirm an account's PQ key before
  accepting a withdrawal.
- `PQCVerifier` treats an inactive precompile as "not verified" (empty
  returndata → `false`) instead of reverting, so the same code runs on a
  local chain, on testnet (precompile active), and — if the precompile ever
  ships there — on mainnet.
- Certificates are unique per `(issuer, documentHash)`; only the issuer can
  revoke. Revoked certificates verify as invalid.

## Known assumptions (to confirm at deploy time)

1. **PQ-proof message encoding:** `issueCertificateWithPQProof` verifies an
   ML-DSA-87 signature over the raw 32-byte document hash
   (`abi.encodePacked(documentHash)`), matching the SDK's
   `pqcVerify({ pubkey, signature, message })` calling convention. If the
   testnet precompile expects a different encoding (e.g. a hashed or
   prefixed message), only that encoding changes — the contract structure
   stays the same.
2. **Frontend PQ-proof issuance is not wired yet:** signing a document hash
   with ML-DSA-87 needs wallet-side ML-DSA signing (QoreX / QoreSign). The
   plain issuance path (hybrid-signed transaction via QoreX) is what the
   frontend uses today and what Quantum Pass requires. The contract-level
   proof path is covered by tests via `MockPQCVerifier`.
3. **Explorer tx links** use `https://explore.qore.network/tx/<hash>`; if the
   explorer uses a different path, paste the hash into its search instead.

## Testnet only

This project targets `qorechain-diana` (EVM chain id 9800) and local dev
chains. The deploy script **refuses mainnet (9801)**. No real funds are
involved anywhere; test QOR comes from the free faucet.
